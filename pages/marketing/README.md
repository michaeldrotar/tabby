# Tabby marketing

Run `pnpm marketing` from the workspace root. The [homepage](http://localhost:5182/) offers one labeled interactive demo, separate tabs/search/settings and theme controls, and a rotating switch to the product video with music and captions. The page speaks directly from Tabby’s maker, with standalone Manage tabs, Find anything, and Make it yours sections and dedicated illustrations rendered with the real tab manager, search, and appearance settings. An interactive [Chrome browser demo](src/BrowserIllustration.tsx) uses a 900 × 600 canvas with the real tab manager and search. Its toolbar button opens search. The product video uses the same browser frame and zooms to each featured area. The hero demo is 20% narrower on desktop. Both demos use independent sample state. The live demo starts with its first tab selected and the Seaglass theme. Six theme choices mix Colorful and Tonal palettes. A sun/moon switch toggles dark mode. Reduced-motion preferences use an instant switch.

The homepage’s [feature illustrations](src/FeatureIllustrations.tsx) render the real [product experiences](../../packages/app/lib/index.ts) with static input. The Chrome browser demo uses live input; its capture view runs the scripted tour. Always compose marketing product visuals from these shared components so they reflect the extension as it changes. [Demo resources](src/demo.ts) provide deterministic sample windows, tabs, bookmarks, history, and recently closed pages. Each demo owns its browser data, views, preferences, and playback. Refresh or Reset restores the samples; the app needs no Chrome permissions.

The header logo hops while visible and idle, taking turns with a shake of the Try it or Watch it sign. Both signs shake after each complete demo/video flip and continue their periodic cues while the switch has focus. The inline SVG banner cat squashes against its floor while scrolling down, lifts with wide eyes while scrolling up, and lands with a springy recovery. The privacy paws alternate full steps, keeping one foot planted against small scrolls, bounding travel between the section’s divider lines, and returning each foot in turn when scrolling stops. The theme-and-icon playground tosses all fifteen theme cards and all twenty-one seasonal icons into a scattered pile near its center. One quiet second after the pieces finish arriving, it starts individual shakes, spins, quick triple spins, and bounces with varied timing and speed, pausing after bursts of 3–5 movements and preserving the pieces’ stacking order. Drag or tap pieces to move them; holding for up to one second doubles the throw speed. The closing cat winks after a quiet pause, and a click or keyboard activation plays an uninterrupted wink and dismisses the automatic cue. The closing install button shakes periodically. Automatic cues pause during interaction, scrolling, or when hidden, and all motion respects reduced-motion preferences.

Use `pnpm test:marketing` for the headless browser workflows, `pnpm -F @extension/marketing type-check` for types, and `pnpm -F @extension/marketing build` for the standalone production app in `build/`.

## Hosting

The public website is [gettabby.org](https://www.gettabby.org/). The hero’s secondary What’s New action and the footer’s Release notes link open the [release history](https://www.gettabby.org/whats-new). This single page renders published release notes as HTML, with a version-and-title index linking to each release. The desktop index and reading column are centered together. The index rail marks the fraction of each release currently visible in the viewport. The index scrolls internally once it reaches its sticky position; scrolling past either end continues scrolling the page. On phones, the sticky version-and-date row opens a bounded version list over the notes, with the selected release highlighted. Selecting a release closes the list. Individual release links work when opened directly or refreshed. The release page downloads alongside its fonts when visited; homepage visitors do not download it.

Run `pnpm marketing:sync-releases` from the workspace root after publishing a GitHub release. The [sync script](../../scripts/sync-marketing-releases.mjs) reads all public, non-prerelease GitHub releases into the checked-in [release snapshot](src/releases.json), ordered by version. It preserves the published titles and note text; the page displays GitHub publication dates and omits duplicate title/version/date lines from the note body. Review and commit the snapshot with the website update. Website builds and visitors use this local snapshot without requesting GitHub. Unpublished extension notes are not included.

For a manual release-history check, open [What’s new locally](http://localhost:5182/whats-new) at desktop and phone widths. Follow both homepage links, use the version index by mouse and keyboard, and refresh a URL with a version fragment. Check the full notes, dates, emphasis, lists, and keyboard shortcuts. Return to the homepage through the Tabby logo.

The [mobile release history](http://localhost:5182/whats-new) shows one version at a time with normal page scrolling. The slim version-and-date row stays available while reading. Version-labelled Newer release and Older release links sit below the note. Swipe or scroll horizontally, or use the links and version chooser to change releases. Each horizontal scroll gesture changes one version. Selecting a release from farther down the page brings its heading into view with a directional transition. Version fragments, browser history, and reduced-motion preferences work in this view. Desktop widths show the continuous history.

The [Tabby marketing project](https://vercel.com/michael-drotars-projects/tabby-marketing) hosts the standalone app on Vercel. Its root directory is `pages/marketing`, with files outside that directory included so the shared workspace packages and brand assets are available. Use Node.js 22.x. [vercel.json](vercel.json) defines the frozen dependency install, preparation of the marketing app's dependencies, Vite build, and output directory. The root URL opens the homepage.

For a manual check, open the homepage at desktop and phone widths. Switch between the hero demo and video through its button; returning to the demo keeps sample changes and pauses the video. Try the Chrome browser demo’s toolbar search and Settings. Use the window picker, select multiple tabs, and open More actions. Check narrow layouts and reduced motion. Videos start muted; the volume choice persists when switching views. Check captions and the Chrome Web Store links.

The [capture view](http://localhost:5182/?capture) records the shared tour inside the Chrome browser frame at 960 × 720, without the surrounding demo controls. With FFmpeg installed, run `TABBY_CAPTURE_MARKETING=1 pnpm -F @extension/e2e exec playwright test --config marketing.config.ts tour.spec.ts` to record the checked tour and update [the video](public/media/tabby-tour.webm) and [its poster](public/media/tour-poster.png). The capture combines the recording with [the soundtrack](public/media/tabby-tour-audio.ogg), which contains original instrumental music. Set `FFMPEG_PATH` to use a specific executable. [Captions](public/media/tabby-tour.vtt) describe its steps. Fonts are served locally with their licenses in [public/fonts](public/fonts).

Run the same browser workflows against a deployment with `TABBY_MARKETING_BASE_URL=https://your-deployment.vercel.app/ pnpm test:marketing`. The URL must end with a slash. Use `pnpm -F @extension/marketing exec vite preview --host 127.0.0.1 --port 5184` to serve the production build locally, then run the workflows with `TABBY_MARKETING_BASE_URL=http://127.0.0.1:5184/`.
