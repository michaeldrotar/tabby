01 / QA feedback & brief

Make the bar the single home for actions.

Issue #24 asks for one selection-aware route for batch actions. The initial close/move/group slice is in place; review feedback expands the work to cover existing row-menu actions and make window selection and action-bar overflow predictable.

QA feedback · incorporated

Keep the tab count from shifting controls; show selected windows, groups, and tabs as icon counts in that order, without “tabs” text. Put all actions behind the ellipsis, keep counts in the action bar, and remove the duplicate count and selected-title headers from its menu. A plain window click selects its active tab; selecting a window also selects its tab groups, while modified window selection includes all tabs. Use target-specific action counts, deduplicate window and tab operations, open the shared menu on right-click with normal selection-preserving behavior, keep notifications above the bar and menus above notifications, suppress collapse/expand success toasts, and show visible color swatches.

Final QA feedback · incorporated

Right-align counts next to ellipsis. A right-clicked window is an action target for all tabs in that window even when its selection originated as a plain active-tab click; keep plain left-click behavior unchanged. Remove inline disabled-reason text but retain the native hover tooltip.

IN SCOPE

One action surface

Tab, group, and window actions live in the ellipsis menu. The bar keeps the selected windows, groups, and tabs counts fixed; right-clicking a row opens that same menu. Submenus replace its contents and keep Back fixed while actions scroll.

IN SCOPE

Complete existing action families

Close, move, group, pin, mute, reload, duplicate, copy, rename, color, collapse/expand, ungroup, and applicable window actions follow selected entities and valid targets.

IN SCOPE

Input-independent replay

Selection transitions accept normalized intents and item order. Batch action runners accept IDs and injected ports so Storybook and autoplay demos use the same behavior without physical events or Chrome.

SEPARATE

Tree view and new command palette

These remain outside Issue #24. Bookmarks are also a follow-up because no current Tabby context menu exposes a bookmark action.

Scope guard: no enabled placeholder action. An action is visible only for a relevant selection and disabled with a clear reason when the selected batch cannot use it. Cross-window tab grouping stays disabled; no selected tabs move implicitly to make grouping work.

02 / The architecture

Keep the product adapters at the edges.

Selection now flows through a pure reducer that accepts normalized click and keyboard intents plus visible item order. React events and Zustand stay in the UI adapter; action runners accept IDs and injected ports, with the Chrome helpers behind one adapter. Replay stories use the reducer and fake action ports without synthesizing browser input or calling Chrome.

App hooks adapt these inputs to Zustand and Chrome, while stories replay the same input sequence with deterministic fixtures and fake ports.

03 / The behavior contract

Resolve once. Execute what the user can see.

SituationExpected behavior
First sidebar openSelect the current window and its active tab once after browser data is loaded. Later focus changes do not overwrite an intentional batch selection.
Plain window clickSelect the window and its active tab only. Its tab groups are selected as entities. A Shift/Cmd/Ctrl window click also selects all tabs in the selected windows.
Direct tabs + groups + windows selectedResolve selected tabs, selected groups, normal-click window active tabs, and modified windows' full tab sets; dedupe and show unique affected tab counts.
Context menu requestRight-clicking a represented selection preserves it; right-clicking an unselected item selects only that item first. A right-clicked window expands its tab targets to the full window while plain window clicks still target the active tab. Both open the shared action menu from the ellipsis. The keyboard Context Menu key opens the same menu.
Selection summaryCounts stay right-aligned next to the ellipsis in windows, groups, tabs order with icon-only labels; the tab count reflects resolved action targets. Each count occupies fixed space and displays 100+ above 99.
Action menuEvery action lives in the ellipsis menu, which opens above its fixed bottom-right trigger. The menu does not repeat counts or selected titles.
Action submenuFrom the ellipsis menu, replace the menu with the submenu and keep a fixed Back action below a bounded, scrollable list.
Delete / BackspaceClose the current selection if the focused item belongs to it; otherwise preserve the existing focused-row close behavior. Ignore text inputs and menu/dialog focus.
Move several tabsOrder IDs from the current browser snapshot, then move in that order. Preserve each source window's tab order. Respect pinned placement, source/target window types, and incognito boundaries. New window uses one created window for the batch.
Existing / new tab groupEnable only when the resolved batch belongs to one window; disable grouping when it spans windows. Group-only actions such as rename require exactly one selected group, with no tabs or windows selected.
Contextual actionsBuild actions from selected types, states, and cardinality. Exactly one group exposes rename; multiple selected groups show rename disabled; a tab or window selection has no group rename option. Window focus and close actions appear directly in the shared menu.
Multi-window operationsResolve selected tabs once across selected windows. One reload action and one copy action use the total selected tab count; no separate window-actions submenu repeats them.
Action countsEach count is based on operation targets. For example, “Remove 2 from group” reflects the two grouped tabs in a larger 18-tab selection.
Notifications and layeringMajor-action notifications appear above the action bar. The action menu and its submenus layer above notifications. Successful collapse/expand operations do not show a toast.
Group colorShow a visible swatch for each available color in the change-color submenu.
Disabled actionsKeep a hover tooltip with the disabled reason, without truncating reason text inline inside the menu.
Partial API failureReturn successful and failed IDs; show “N of M tabs …” and preserve failed tabs in selection when they still exist.
Tabs disappear or move externallyPrune stale selected entities, update counts, and move keyboard focus to a surviving nearby item without selecting unrelated tabs.
Empty / stale selectionNo action is enabled. Empty batches make no API calls and do not report a success.
Product choice · resolved

Batch grouping is disabled across windows; tabs stay in their current windows. Contextual actions derive from the selected batch and operation: selection-wide tab operations use resolved IDs; group rename requires exactly one selected group; selecting two groups disables rename; a single selected tab has no group rename option.

04 / Implementation order

Build the stable seams before wiring buttons.

  1. Sync and preserve work. Fast-forward next to merged PR #23 before resolving the saved batch implementation.
  2. Model window intent precisely. Keep mouse and keyboard modifiers normalized. Represent plain-window active-tab selection separately from modified full-window selection; select the current window and active tab once on first load.
  3. Resolve once. Expand groups and explicitly expanded windows, resolve plain windows to active tabs, dedupe overlaps, and sort by window order and tab index.
  4. Run every batch operation through ports. Keep close, move, group, pin, mute, reload, duplicate, and copy away from direct Chrome calls; return per-tab outcomes and handle aggregate clipboard actions once.
  5. Make the bar the only action surface. Remove row context-menu wrappers and bring applicable tab, group, and window commands into the contextual action set. Keep group and window cardinality constraints explicit.
  6. Finish the action bar geometry. Reserve the selection-count notch without moving controls; cap counts at 100+; always put ellipsis at the final visible slot; anchor overflow above its bottom-right trigger.
  7. Build submenu navigation. Place bar submenus above center; overflow submenus replace overflow contents, with a bounded scrolling body and a fixed Back control.
  8. Recover and prove. Reconcile stale IDs and focus; test selection model, action runner, action visibility, partial failures, geometry, and fake-port demos; update release notes and record manual QA.

05 / Verification

Test the rule, the wiring, and the browser edges.

Pure model and action tests

  • Click, Shift+click, Cmd/Ctrl+click, Space-to-enter then Space-toggle, Shift+Arrow, Escape, and select-all as plain intent sequences.
  • Plain click on a window resolves only its active tab; Shift/Cmd/Ctrl window interactions resolve every tab in the selected windows.
  • Initial selection is current window + active tab exactly once; focus changes do not replace a user-edited batch.
  • Reverse / extending ranges, repeated toggles, collapsed-group visible order, pane changes, empty lists, and deleted anchor items.
  • Mixed selected windows / groups / direct tabs resolve to unique tab IDs; overlaps do not double count.
  • All old tab/group/window menu actions appear only in valid action-bar contexts; rename is disabled for multiple groups and absent for tab-only selection.
  • Mixed pinned, muted, audible, grouped, and unavailable tabs yield valid batch pin/mute/reload/duplicate/copy behavior.
  • Source-window and tab-index ordering; pinned/unpinned placement; normal vs. popup/devtools; incognito mismatch; stale ID handling.
  • Each port can fail independently; counts and failures remain correct for zero, complete, and partial success. Fake ports prove that core code has no Chrome dependency.

Integration and browser scenarios

  • Action menu and Delete / Backspace close the same selected tabs; right-click from tabs, groups, and windows opens the shared menu without the old row menus.
  • Plain and modified clicks on a window produce the expected selected-item counts and tab targets.
  • Move across two normal windows and verify order in the destination.
  • Move selected tabs to one new window; verify the original order.
  • Move a mixed pinned, grouped, and ungrouped selection.
  • Group from a collapsed group and verify unique affected tabs.
  • Partial close / move / group failure reports actual affected IDs.
  • Close the active tab plus neighbors; verify selection and focus recovery.
  • External Chrome close/move updates counts and clears stale focus.
  • Keyboard action does not run while typing in an input; Context Menu key focuses action-bar overflow.
  • Count notch width stays fixed at 0, 1, 99, 100, and larger entity counts; windows, groups, tabs order and controls stay fixed as selection changes.
  • Ellipsis menu opens directly above its trigger; its submenus scroll while Back remains fixed. Notifications do not block the bar or menu.
  • Action labels use operation-specific target counts; grouped-tab removal counts only grouped tabs.
  • Right-click preserves a selection containing the clicked row and selects an unselected row before opening the shared menu; a window's tab targets expand to all of its tabs.
  • Disabled actions have no inline reason text and retain a hover tooltip.
  • Group color submenu visibly shows every swatch; routine expand/collapse actions remain silent.
  • Replay equivalent mouse and keyboard intent scripts against fake data.
  • Check responsive action-bar overflow and light/dark appearances.
